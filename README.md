## 增强功能

- **手动全文建档**：点击开始后读取可提取的逐页文本，整理背景、方法、符号与术语表；仅打开论文不触发增强模块的模型请求。
- **按任务选择模型**：通读、翻译和解释各有模型设置；新配置默认通读 `gpt-5.6-sol`、翻译/摘录整理 `gpt-5.6-luna`、解释跟随聊天栏，已有个人选择保持不变。打开可见面板自动加载 Codex 目录，每 10 分钟检查一次，支持立即手动刷新；新增模型无需修改插件。目录取决于 Zotero 配置的 Codex 运行程序，并不保证账户调用权限。退出目录的已选模型保留并标记，要求用户重选，不会静默改用其他模型。
- **结合全文翻译和解释**：建档成功后，将本篇全文及背景用于后续问题，校验论文身份，避免串到其他文章。
- **额度显示**：读取当前登录账户返回的用量窗口，显示剩余比例；失败或过期时明确标识。读取额度本身不发起推理。
- **Zotero / Obsidian 笔记**：背景、讨论、PDF 已添加文本、AI 答复及选区可载入可编辑预览，再手动保存；可以按论文或 Zotero 分类设置目标仓库和子文件夹。
- **PDF 提取兼容**：优先使用 Zotero 逐页统计，兼容明确的分页符，并在缺少页映射时尝试本篇的 Zotero 全文缓存。

## 安装与使用

1. 备份 Zotero 数据和设置，从本仓库 [Releases](https://github.com/Jerry-Li-J/llm-for-zotero-paper-companion/releases) 下载审核版 XPI。
2. Zotero → 工具 → 插件 → 齿轮 → 从文件安装，选择 XPI。
3. 本分支沿用上游插件 ID 和设置，因此会**替换原版**，不支持两者并装。它使用本仓库的更新地址；当前更新清单为空，只手动更新。其他独立翻译插件可以保留，但需要自行避免重复开启自动翻译。
4. 配置并登录自己的模型运行环境；增强建档、翻译和解释工作流面向 Codex 会话。连接方法见保留的上游说明；不要上传登录文件或密钥到仓库。
5. 打开 PDF，展开“论文伴读”，选择可用模型，然后手动点击“开始通读”。检查结果中的覆盖情况和解析局限。
6. 选中 PDF 文字，通过原插件将选区添加到当前对话，再点击“翻译选区”或“解释选区”。
7. 在 Obsidian 笔记区域选择自己的仓库/文件夹，记住本篇目标或绑定分类；载入预览、修改后保存。公开版不按任何个人仓库名称猜测保存位置。

坚果云等云同步由你自己配置的桌面客户端或 Obsidian 同步插件负责；本增强模块只写入本地 Markdown，不内置云账号和同步凭据。同一设备上的同一仓库应避免两个同步机制重复管理。

## 限制和数据流

- **不承诺读懂所有 PDF。** 扫描件需要 OCR；空页、无法验证的页覆盖、加密或损坏文件可能拒绝建档。文字提取不等于图表和复杂公式的视觉审阅。
- 当前单次全文估算上限为约 90,000 tokens，是保护性启发式值，不是任何模型的官方容量保证。超限会停止，不提供自动分段/OCR。
- 建档和后续解释会把本篇提取全文、背景及当前问题发送给选定模型服务；重复使用全文仍可能消耗较多额度。“背景缓存”不保证免费或模型端命中缓存。
- 背景记录包含提取文本，保存在 Zotero 数据目录的 `qin-paper-companion` 子目录；导出笔记保存在用户选择的仓库。配置信息使用原插件的偏好设置。
- 完成标记仅检测输出结束状态，不能证明模型没有遗漏或理解错误；学术结论、公式和译文需对照原文核验。
- 原插件已有的其他功能、联网行为和权限仍适用。增强模块的“手动触发”说明不代表对所有上游功能的独立审计。

## 开发与构建

根目录保留对应版本完整的上游源码、依赖锁文件及构建配置。`paper-companion/` 包含新增的可编辑源码、测试及补丁构建器。当前实现是在固定上游打包脚本中插入增强代码；这是可审计的过渡方案，还不是直接集成到 TypeScript 模块的长期维护重构。

详细步骤见 [BUILD.md](BUILD.md)。只运行本地增强回归测试：

```sh
node --test paper-companion/test-core.cjs paper-companion/test-adapter.cjs paper-companion/test-quota.cjs paper-companion/test-obsidian.cjs paper-companion/test-obsidian-ui.cjs
node --test paper-companion/test-models.cjs
```

这些测试不调用真实模型，不需要凭据。上游的完整测试及真实 Zotero 端到端验证是另外的工作，不能用上述测试通过替代。
